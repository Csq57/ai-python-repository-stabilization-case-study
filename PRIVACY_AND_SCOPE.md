# Privacy and Scope

## What this public package contains

- an engineering process case study;
- dated verification summaries;
- newly created conceptual diagrams;
- a domain-neutral fictional phase specification;
- a fictional audit report; and
- a fixed-scope service description.

## What it does not contain

- OpenTrendIQ Lite product source code;
- private repository URLs or internal file paths;
- credentials, environment values or account information;
- customer code, records or testimonials;
- production data or unredacted personal data;
- trading signals, portfolio output or investment advice;
- claims about investment accuracy or returns; or
- claims of completed client engagements.

## Client access boundary

Prospective clients should share only material they own or are authorised to
share. A sanitised copy or agreed read-only access is preferred for diagnosis.
Live credentials, production passwords and unredacted customer data are not
accepted.

Any implementation work is performed only after scope, access, protected
behaviour and acceptance checks are confirmed in writing.

## Assurance boundary

A repository stabilisation audit identifies engineering workflow, reliability,
test and handover risks within an agreed scope. It is not penetration testing,
formal security assurance, legal review or compliance certification.
